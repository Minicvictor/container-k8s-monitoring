# Container & Kubernetes Monitoring Lab

## 1. Project Overview

This project sets up monitoring for both plain Docker containers and a Kubernetes workload.
It covers four layers: `docker stats` and cAdvisor for Docker-level visibility, a Kubernetes
Deployment/Service for the actual workload, and a Prometheus + Grafana stack (installed via Helm)
for cluster-wide metrics collection and dashboarding. A deliberate failure is also simulated to
demonstrate using the monitoring data to diagnose a real problem, not just to look at graphs.

## 2. Environment

```
OS: Ubuntu 24.04
Docker: 28.x
Kubernetes: Minikube
Helm: 3.x
```

## 3. Deployment Instructions

Clone this repository, then:

```bash
# Docker containers
docker run -d --name web1 -p 8081:80 nginx
docker run -d --name cache1 -p 6379:6379 redis
docker run -d --name db1 -e POSTGRES_PASSWORD=pass -p 5432:5432 postgres

# cAdvisor
docker run -d \
  --volume=/:/rootfs:ro \
  --volume=/var/run:/var/run:ro \
  --volume=/sys:/sys:ro \
  --volume=/var/lib/docker/:/var/lib/docker:ro \
  --publish=8080:8080 \
  --detach=true \
  --name=cadvisor \
  gcr.io/cadvisor/cadvisor

# Kubernetes workload
kubectl apply -f k8s/deployment.yaml
kubectl apply -f k8s/service.yaml

# Monitoring stack via Helm
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
kubectl create namespace monitoring
helm install monitoring prometheus-community/kube-prometheus-stack -n monitoring
```

## 4. Docker Monitoring

Container resource usage was inspected with `docker stats` (CPU, memory, memory limit, network
I/O, block I/O, and process count) and with cAdvisor’s web interface and Prometheus-compatible
metrics endpoint at `http://localhost:8080`. Full details and evidence:
[`docker/README.md`](docker/README.md).

## 5. Kubernetes Monitoring

A Deployment with 3 replicas of nginx and a matching Service were created (see
[`k8s/deployment.yaml`](k8s/deployment.yaml) and [`k8s/service.yaml`](k8s/service.yaml)), each
container configured with CPU/memory requests and limits. Pod status was checked with
`kubectl get pods`.

## 6. Prometheus

Prometheus was installed as part of the `kube-prometheus-stack` Helm chart and accessed via
`kubectl port-forward`. Six PromQL queries covering CPU, memory, pod info, restarts, replica
counts, and node metrics are documented with results in
[`prometheus/queries.md`](prometheus/queries.md).

## 7. Grafana

Grafana was accessed via `kubectl port-forward` using credentials generated by the Helm
installation. A 6-panel dashboard (CPU usage, memory usage, pod count, pod restarts, deployment
replicas, node resource usage) was built using Prometheus as the data source. Full panel details:
[`grafana/dashboard.md`](grafana/dashboard.md).

## 8. Troubleshooting Exercise

A failed Deployment rollout was intentionally triggered using a bad image tag, observed through
both `kubectl` and the Grafana replicas panel, then resolved by rolling back to a valid image.
Full writeup: [`k8s/troubleshooting.md`](k8s/troubleshooting.md).
